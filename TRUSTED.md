## Trusted base (from the design spec)

- rustc, Verus (including its `by (compute)` interpreter), Z3, and vstd's specs of std.
- The OS UDP stack, the clock, and getrandom (used for connection IDs, stateless-reset tokens, and each TLS handshake's `TLS_RAND_LEN` bytes: the ServerHello random, the ECDHE scalar and the PSS salt).
- The unverified IO shell and the `main` binary, including loading the certificate chain and parsing the PEM/PKCS#8 P-256 private key and, when configured, the PKCS#8 RSA private key.
- **The hand-written Verus formalization of each RFC** (`spec` modules). Proofs show the code matches these specs; they can't show the specs match the RFC text. Keeping the specs small and readable, with each one citing its RFC section, is how the risk stays manageable.
- vstd models a `Vec`'s length, not its capacity, so every proven memory bound (e.g. `quic::reassembly`'s `phys_len() <= 2 * buf_len()` and `RecvStream`'s `buffered_phys()`) bounds lengths only. `Reassembly::pop` releases both allocations on a full drain by construction (fresh `Vec`s, and `split_off` keeps only the tail allocation); the unverified test-only accessor `Reassembly::capacities` checks it in `tests/reassembly.rs` (`drain_releases_capacity`); likewise `SendStream::on_data_acked` replaces its buffer with a fresh `Vec` once everything written is acknowledged, checked through `SendStream::buf_capacity` in `tests/send_stream.rs` (`ack_releases_capacity`; `ack_copies_linear` uses it to count the bytes its lazy trims copy).
- **Temporary:** each crypto `external_body` backed by the RustCrypto shim (phases 3-4). Phase 5 removes every one of these entries.

## Pinned versions

- Verus 0.2026.10.04.426d8b0 (toolchain 1.98.1)
- Z3 4.16.0 (bundled with Verus)
- vstd 0.0.0-2026-10-04-0306 (must equal the pin in vest_lib 0.2.2)

The shipped artifact is built by `cargo build --release` with rustc 1.98.1, pinned by `rust-toolchain.toml`, which is Verus's own toolchain, so the compiler that checks the proofs is the compiler that builds the binary. The release profile keeps overflow checks on, except in the verified crates (per-package overrides in `Cargo.toml`), where Verus proves the absence of overflow. `verus!` erasure is done by `verus_builtin_macros` (version from `Cargo.lock`, currently 0.0.0-2026-09-20-0158).

- Test-only (crates/tls dev-dependencies, not in the trusted base; `cargo tree -e normal` contains none of them). These are the Cargo.lock entries this phase adds:
  - ring =0.17.14, with untrusted 0.9.0 and the getrandom 0.2.17 *crate*, which is test-only and distinct from the trusted OS getrandom above;
  - ring's build/platform entries: cc 1.6.0, shlex 2.0.1, find-msvc-tools 0.1.14, wasi 0.11.1+wasi-snapshot-preview1, windows-sys 0.52.0, windows-targets 0.52.6 and windows_* 0.52.6;
  - rustls =0.23.45 (Task 7), with rustls-webpki 0.103.15, rustls-pki-types 1.15.1 and once_cell 1.21.4. Its subtle 2.6.1 and zeroize 1.9.1 were already locked by the RustCrypto shim.
- RustCrypto shim (crates/crypto), removed in phase 5: sha2 =0.11.1, rsa =0.10.0-rc.19 (dev: p256 =0.14.0, primeorder =0.14.0, rsa with hazmat, hmac =0.13.0, hkdf =0.13.0, aes =0.9.3, aes-gcm =0.11.1); transitively pinned by Cargo.lock in `cargo tree -p crypto -e normal`: crypto-bigint 0.7.10, crypto-primes 0.7.2, digest 0.11.3, signature 3.0.0 (rfc6979, ecdsa and elliptic-curve are now dev-only, through p256)
