# Phase 2a: HTTP/3 Frame + QPACK Codecs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verified, sans-IO codecs for the HTTP/3 layer, each proven against an RFC-transcribed spec:
- HTTP/3 frame codec;
- QPACK prefixed integers;
- QPACK static table;
- Huffman decoding;
- request field-section decoding and response field-section encoding;
- capacity-0 handling of the encoder and decoder streams.

Phase 0–1 carry-overs and the RSA scope decision also land here.

**Architecture:**
- **New crate `crates/h3`**, which depends on `wire` by path.
- **HTTP/3 frames** are built with Vest from `wire::varint::QuicVarInt`.
- **QPACK is hand-written** spec + exec code with no Vest. Its prefixed integers share their first byte with flag bits, which Vest combinators don't model cleanly.
- **The two big trusted tables** are generated by `scripts/gen_tables.py` from RFC appendix text committed in `crates/h3/rfc/`. A Rust test re-parses that same text and checks every entry.
- **All error results are RFC error codes as `u64`.** Connection-vs-stream classification is Phase 2b's job.

**Tech Stack:** Verus 0.2026.10.04.426d8b0, vstd `=0.0.0-2026-10-04-0306`, vest_lib `=0.2.2`, duvet 0.4.3, Python 3 (stdlib only, for the generator).

**Spec:** `docs/superpowers/specs/2026-10-27-verified-http3-design.md`

## Global Constraints

- **Pins:** Verus 0.2026.10.04.426d8b0, vstd `=0.0.0-2026-10-04-0306`, vest_lib `=0.2.2`. Never upgrade one alone.
- **No escapes in `crates/`:** zero `assume`, `admit`, `external_body`, `assume_specification`, `#[verifier::external*]` or `axiom`. Any unavoidable non-`verus!` code, such as the `Clone`/`Copy` impls, gets a note in `TRUSTED.md`.
- **Duvet citations:** every RFC-transcribed spec fn carries a `//= https://www.rfc-editor.org/rfc/rfcNNNN#section-X` + `//#` citation whose quote is contiguous RFC text.
- **Every task's verification step runs all four checks:**
  - `scripts/verify.sh` reports 0 errors;
  - `cargo build && cargo test` pass with 0 warnings;
  - the escape grep finds nothing;
  - `duvet report` exits 0.
- **Verification evidence must come from a fresh `CARGO_TARGET_DIR`.** A cargo cache hit prints nothing. To get the evidence, run `cargo verus verify` in the crate with `CARGO_TARGET_DIR=<scratch>/vt-<task>`.
- **Sans-IO:** no async, no trait objects, and no closures in exec code. No panics on any input. No allocation sized by an untrusted length before checking it against the bytes actually present.
- **Error codes (`h3::codes`)**, from RFC 9114 §8.1 and RFC 9204 §6:

  | Code | Value | Code | Value |
  |---|---|---|---|
  | H3_NO_ERROR | 0x100 | H3_REQUEST_REJECTED | 0x10b |
  | H3_GENERAL_PROTOCOL_ERROR | 0x101 | H3_REQUEST_CANCELLED | 0x10c |
  | H3_INTERNAL_ERROR | 0x102 | H3_REQUEST_INCOMPLETE | 0x10d |
  | H3_STREAM_CREATION_ERROR | 0x103 | H3_MESSAGE_ERROR | 0x10e |
  | H3_CLOSED_CRITICAL_STREAM | 0x104 | H3_CONNECT_ERROR | 0x10f |
  | H3_FRAME_UNEXPECTED | 0x105 | H3_VERSION_FALLBACK | 0x110 |
  | H3_FRAME_ERROR | 0x106 | QPACK_DECOMPRESSION_FAILED | 0x200 |
  | H3_EXCESSIVE_LOAD | 0x107 | QPACK_ENCODER_STREAM_ERROR | 0x201 |
  | H3_ID_ERROR | 0x108 | QPACK_DECODER_STREAM_ERROR | 0x202 |
  | H3_SETTINGS_ERROR | 0x109 | | |
  | H3_MISSING_SETTINGS | 0x10a | | |

- **Frame types** (RFC 9114 §7.2, §11.2.1):
  - DATA 0x00, HEADERS 0x01, CANCEL_PUSH 0x03, SETTINGS 0x04, PUSH_PROMISE 0x05, GOAWAY 0x07, MAX_PUSH_ID 0x0d;
  - HTTP/2-era reserved: 0x02, 0x06, 0x08, 0x09.
- **Settings** (RFC 9114 §7.2.4.1, RFC 9204 §5):
  - QPACK_MAX_TABLE_CAPACITY 0x01, MAX_FIELD_SECTION_SIZE 0x06, QPACK_BLOCKED_STREAMS 0x07;
  - HTTP/2-era reserved (receipt is H3_SETTINGS_ERROR): 0x02, 0x03, 0x04, 0x05;
  - 0x00 is registry-reserved but was never defined in HTTP/2, so it's ignored like any unknown identifier;
  - grease: `0x1f * N + 0x21`.
- **Matrix bookkeeping:** in its own commit, each task suffixes the Notes column of the `docs/requirements.md` rows it closes with `✅ 2a: <file>`.
- **Frame-type varints may be non-minimal.** RFC 9114 has no shortest-encoding rule (RFC 9000 §12.4's rule applies to QUIC frames only), so parse with `QuicVarInt<false>`.

## Matrix rows this plan closes

- **RFC 9204:** all Phase-2 rows except §4.2 (encoder/decoder stream uniqueness and criticality goes to 2b). That covers §2.1, §2.1.2 (req), §2.2, §2.2.1, §2.2.3, §3.1, §3.2.2 (req), §3.2.3 (req), §4.1.1, §4.3.1 (req), §4.4.1, §4.4.3, §4.5.1.1, §4.5.1.2, §4.5.4 and §7.4.
- **RFC 9114:**
  - §7.1 and §10.8 (frame layout and length exactness);
  - the layout-level parts of §7.2.3, §7.2.4, §7.2.5, §7.2.6 and §7.2.7 (single-varint payloads, SETTINGS duplicates);
  - §7.2.4.1 (reserved setting IDs) and §7.2.8 (recognizing reserved frame types).
- **Everything else in Phase 2 goes to Phase 2b:** frame placement per stream type, stream types, the control stream, GOAWAY semantics, message validation, §4.x, §6.x and §7.2.4.2.

## Review Focus

1. **Huffman padding edge cases:** 0–7 trailing one-bits are accepted; 8+ ones, padding containing a zero bit, and an embedded EOS code are rejected. Pinned in Task 5: `huffman_padding`.
2. **Prefix integers at the 62-bit edge:** the minimal encoding of 2⁶²−1 must decode for every prefix width N=1..8, and 2⁶² must be rejected. Pinned in Task 3: `prefix_int_62bit_all_widths`.
3. **A field-section string length larger than the remaining bytes** must return QPACK_DECOMPRESSION_FAILED without allocating that length. Pinned in Task 6: `string_length_overflow`.
4. **Dynamic-table references at capacity 0:** RFC 9204 B.2's encoder stream, field section and decoder stream each produce the right error. Pinned in Tasks 6 and 7: `b2_rejected`.
5. **Frame payload length mismatch:** a GOAWAY whose payload has one byte too many or too few, and a SETTINGS payload ending mid-pair, each return H3_FRAME_ERROR. Pinned in Task 2: `frame_layout_errors`.

### Task 3: QPACK prefixed integers

**Files:**

**Interfaces:**
- Produces (`h3::qpack::int`):
  - `pub const PREFIX_INT_MAX: u64 = 0x3FFF_FFFF_FFFF_FFFF;`
  - `pub const PREFIX_INT_MAX_CONT: usize = 10;` This is the cap on continuation bytes. Ten bytes cover 62 bits even when N=1, since (62−1)/7 rounds up to 9, plus one spare byte for padding.
  - `pub enum PrefixInt { Incomplete, Value { value: u64, consumed: usize }, TooLarge }`
  - `pub fn parse_prefix_int(n: u8, buf: &[u8]) -> PrefixInt`, which requires `1 <= n <= 8`. The prefix is the low `n` bits of `buf[0]`; the caller owns the high bits.
    - `TooLarge`: the value exceeds PREFIX_INT_MAX, or more than PREFIX_INT_MAX_CONT continuation bytes.
    - `Incomplete`: `buf` is empty, or it ends while the continuation bit is still set and no limit has been exceeded.
  - `pub fn serialize_prefix_int(n: u8, flags: u8, v: u64, out: &mut Vec<u8>)`. It requires `1 <= n <= 8`, `v <= PREFIX_INT_MAX`, and `flags` with no bits inside the low `n`. The encoding is minimal.
  - Spec: `rfc_prefix_int(n, b) -> PrefixIntSpec`, transcribed from the RFC 7541 §5.1 decoding pseudocode, with the limits above as the RFC 9204 §7.4 implementation limits.
  - Theorems: exec ≡ spec, and `parse(n, serialize(n, f, v)) == Value{v, len}`.

### Task 5: Huffman decoder (proof-heavy; BLOCKED is an acceptable outcome)

**Files:**
- Create: `crates/h3/src/qpack/huffman.rs`
- Test: `crates/h3/tests/huffman.rs`

**Interfaces:**
- Consumes: `spec_huff_code` and `huff_code` from Task 4.
- Produces (`h3::qpack::huffman`):
  - Spec fns:
    - `spec fn code_bits(sym: nat) -> Seq<bool>`: the MSB-first bits of `spec_huff_code(sym)`;
    - `spec fn encode_bits(s: Seq<u8>) -> Seq<bool>`: the concatenation of `code_bits(s[i])`;
    - `spec fn bytes_to_bits(b: Seq<u8>) -> Seq<bool>`: MSB-first;
    - `pub open spec fn rfc_huffman_decodes(input: Seq<u8>, s: Seq<u8>) -> bool`: `exists|k: nat| k <= 7 && bytes_to_bits(input) == encode_bits(s) + Seq::new(k, |_| true)`.
  - This spec captures all three RFC 7541 §5.2 decoder errors:
    - more than 7 padding bits matches no `s`;
    - non-EOS-prefix padding (a zero bit) matches no `s`;
    - an EOS code inside the input matches no `s`, because `s` holds bytes only, EOS is 30 one-bits, and the padding has at most 7.
  - `pub fn huffman_decode(input: &[u8]) -> (r: Option<Vec<u8>>)` ensures:
    - `r matches Some(s) ==> rfc_huffman_decodes(input@, s@)`;
    - `r is None ==> forall|s: Seq<u8>| !rfc_huffman_decodes(input@, s)`.
  - **No Huffman encoder.** Responses use H=0 literals.

- [ ] **Step 1: Failing tests:**
  - `rfc7541_c4_strings`: the RFC 7541 C.4.1–C.4.3 Huffman strings decode to `www.example.com`, `no-cache`, `custom-key` and `custom-value`. Extract the exact hex from rfc7541.txt C.4; `www.example.com` is `f1e3 c2e5 f23a 6ba0 ab90 f4ff`.
  - `huffman_padding`:
    - an empty input decodes to an empty output;
    - `[0xff]` (8 one-bits of padding) → `None`;
    - `www.example.com` with its last byte's padding bits changed to contain a 0 → `None`;
    - `[0xff, 0xff, 0xff, 0xff]` (EOS's 30 ones plus 2 padding ones) → `None`;
    - every single byte `0..=255` encoded by a test-local reference encoder built from `huff_code` decodes back to itself.
- [ ] **Step 2:** Run the tests and confirm they fail.
- [ ] **Step 3: Implement.** Proof route to try first:
  - **(a) Prefix-freeness and "no code is all ones",** established over the whole table. Try `assert(...) by (compute)` on a 16-entry slice first and time it. If it's fast, extend it to all 257 entries. Otherwise prove the canonical-code structure: codes sorted by (len, sym) increase by `(prev + 1) << (len - prev_len)`, which implies prefix-freeness.
  - **(b) The exec decoder** walks bits MSB-first and, at each bit length, checks against the canonical ranges. The loop invariant is that the prefix decoded so far equals `encode_bits(out)` followed by the pending bits.
  - **(c) Rejection completeness** follows from uniqueness of decomposition under prefix-freeness.

### Task 7: Encoder and decoder stream instructions at capacity 0

**Files:**
- Create: `crates/h3/src/qpack/instructions.rs`
- Test: `crates/h3/tests/qpack_instructions.rs`

**Interfaces:**
- Consumes: `parse_prefix_int` and the QPACK error codes.
- Produces (`h3::qpack::instructions`):
  - `pub fn process_encoder_stream(buf: &[u8]) -> (r: Result<usize, u64>)`. This handles the peer's encoder-stream bytes (RFC 9204 §4.3).
    - `Ok(n)`: `buf[..n]` is a sequence of complete valid instructions. The only valid one at capacity 0 is Set Dynamic Table Capacity `001…` (5-bit) with value 0. `buf[n..]` is a strict prefix of one instruction, so the caller keeps it.
    - `Err(QPACK_ENCODER_STREAM_ERROR)` as soon as an instruction is known to be invalid. An Insert or Duplicate opcode is invalid as soon as its first byte is seen; a capacity is judged once it has been fully parsed. Invalid cases:
      - capacity > 0 (§4.3.1);
      - Insert With Name Reference `1T…` or Insert With Literal Name `01H…` (§3.2.2: entry larger than capacity 0);
      - Duplicate `000…` (§2.2.3: invalid reference);
      - a prefix int that is `TooLarge`.
  - `pub fn process_decoder_stream(buf: &[u8]) -> (r: Result<usize, u64>)`, for the peer's decoder-stream bytes (§4.4). It has the same `Ok(n)` meaning.
    - Stream Cancellation `01…` (6-bit) is valid.
    - Section Acknowledgment `1…` (7-bit) is invalid (§4.4.1: we never send dynamic references).
    - Insert Count Increment `00…` (6-bit) is invalid (§4.4.3: any increment is beyond the 0 we sent).
    - Errors are `Err(QPACK_DECODER_STREAM_ERROR)`.
  - Spec: `rfc_encoder_stream(b) -> Result<nat, u64>` and `rfc_decoder_stream(b) -> Result<nat, u64>`. The exec functions are proven equal to them.
