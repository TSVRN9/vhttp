# RCA: the R4 acceptance parser silently skipped fns

- **Defect:** `tools/acceptance.py` (9r R4, 60d7c0f) is a syntactic Python scan of Verus source. It silently dropped 22 exec fns in the tree (a same-line `ensures .. {` body made it swallow the following fns, crediting one fn with another's clause), ignored the in-tree `R<T> = Result<T, Halt>` alias (about 45 fns), accepted any identifier containing `allowed_` (a struct field, `ack_only_allowed_spec`) as the clause, and never ran the vacuity check on `spec(checked) fn`. The baseline could also grow, so appending a line silenced the gate.
- **Escape:** the demos tested only positive fixtures written by the same author, in the layout the parser was written for, so each bug sat outside every fixture. The header claimed unformatted code was rejected; nothing checked that. The gate's own count (147) was never compared with an independent one, and the only reviewer cross-check reused the parser's lexer.
- **Class:** C4 (a gate that can pass with part of its input unchecked), and C6 (a claim, "rejects rather than guesses", pinned by no test).
- **Catch:** the fail-closed raises (a clause text containing another `fn`, an unsplittable signature, bodyless allowed fns, `verus!(..)` blocks); `MAX_BASELINE` plus the merge-base check, so the baseline cannot grow; alias collection and a named allowed-spec set; a raise when the chosen body brace sits on a line not indented under its fn (the fn body was read as clause text), and a cross-count: `scripts/acceptance.sh` counts `fn` tokens in col-0 `verus! {` blocks with a separate awk scan and fails if the parser's examined-fn total differs (4748 on the tree).
- **Known limit of the cross-count:** the parser reaches every fn token by construction, so the count guards lexing and block discovery only. It cannot see a fn credited with the wrong clause text; the body-brace raise is what covers that.
- **Closed (9r2 R5):** on main the ratchet files were compared only with `HEAD^1`, so growth spread over several direct commits passed. `tools/ratchet_walk.py` now walks the first-parent history from the commit that introduced the file and fails on any step that adds a line (rlimit-ceilings: a new line or a raised value; rfc-quantity-open: a new line or a raised count). One walk serves `tools/acceptance-baseline.txt`, `tools/rlimit-ceilings.txt` and `tools/rfc-quantity-open.txt`. The working tree is the walk's last step (an uncommitted shrink then re-grow fails); the HEAD^1 comparison on main was deleted as redundant. A git error or a shallow clone fails. A deleted-then-re-added file is compared with its last copy. `tools/rfc-quantity-allow.txt` needs no walk: it is pinned by ALLOW_DIGEST inside `tools/rfc_quantity.py`, so any change shows in that tool's diff.
- **Evidence:** `scripts/gate-demos.sh` has a demo per bug: same-line body brace, field name, `ack_only_allowed_spec`, `spec(checked)` with body `true`, alias, unsplittable signature, cross-count mismatch, appended baseline line, body read as clause text, defaulted-generic alias, `use .. Result as ..` (refused, not resolved), `ensures_` identifier, duplicate baseline line, and the real-git merge-base path in a throwaway repo (branch growth, main growth against HEAD^1, no main).
- **Evidence (R5):** gate-demos: growth over two direct commits on main fails for each of the three files (the last commit not growing, so HEAD^1 alone passes); a shrink then a re-grow fails; a legitimate shrink passes; a deletion then a larger re-add fails; a shallow clone fails.
