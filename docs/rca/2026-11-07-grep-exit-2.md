# RCA: grep exit 2 read as "no match" in ct-check's report reader

- **Defect:** `grep '^reject ' "$report" >&2 && fail "crypto: rejects (above)"` in the crypto report reader of `scripts/ct-check.sh` passes when `$report` is missing or unreadable: grep exits 2, `&&` does not fire. Present since 0d12bb5 (the commit that introduced the line); found during 9r2 T6 when the reader was factored into `scripts/ct-report.sh` to be demoed. The same idiom stood at the selftest, parser-selftest and semconf `grep -v '^pass ' .. && fail` checks (ct-check.sh), and two `if grep ..` verdicts (ct-binary.sh, ct-check.sh). T6 3e190fa guarded the reader; the fix round replaced every site with `grep_hits`.
- **Escape:** the reader was inline in ct-check.sh, which runs a 5-minute pipeline and cannot be fed a canned report, so no demo could reach it. It was protected only by an upstream step (`front` fails unless the report file exists), so it looked safe in every run; nothing tested the check itself. Review read the line as a negative check and `&&` as fail-closed, which it is only for exit 0 and 1.
- **Class:** C4 (a gate that can pass with nothing checked: a tool or input missing).
- **Catch:** (1) `grep_hits [-v] PATTERN FILE..` in `scripts/ct-lib.sh`: returns 0 on a match, 1 on none, and fails on a missing file or a grep exit of 2 or more; every verdict site uses it (ct-check.sh x4, ct-report.sh, ct-binary.sh). (2) `scripts/lint-scripts.sh` rejects, in any scripts/*.sh, `grep .. && fail|die|err|exit`, `if grep`, `! grep`, `while grep` and `until grep` outside comments, so a new bare verdict fails verify.sh. `grep .. || fail` (a required match, exit 2 also fails) and `grep .. || true` counts are allowed.
- **Limit:** the lint is a line pattern: a verdict split across lines, or `grep` behind a variable or `xargs`, is not seen. A `$(grep .. || true)` whose empty value is then tested for emptiness passes on a missing file; those sites compare counts or expect a non-empty value and fail closed.
- **Evidence:** `scripts/gate-demos.sh`: lint rejects `grep .. && fail` and `if grep ..` and passes the `grep_hits` form, `grep .. || fail` and a comment; `grep_hits` returns on a match, returns 1 on none, and fails on a missing file, a missing file among others, an invalid pattern (exit 2) and no file argument; ct-report demos cover a missing and an empty report.
