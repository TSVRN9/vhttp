# RCA: 2026-11-07 repo audit (main 14a6cf1)

## 1. verify.sh did not run the workspace tests

- **Defect**: `scripts/verify.sh` ran the proofs, duvet, the CT checks and the 9r gates, but not `cargo test --workspace` (only `ct-check.sh`'s ctmir tests). The unverified shell (`crates/server`: PEM, base64, PKCS#8, the address/PathId table, spoofed-address slots) has no proofs, so its tests were its only guard and nothing gated them.
- **Escape**: tests were run by hand per task (plan Global Constraints, "cargo test --workspace stays green"), a prose rule. verify.sh's exact final line was the green signal, and it said nothing about tests.
- **Class**: C4 GATE FAIL-OPEN (the green signal omits a check the process relies on); C18 UNVERIFIED SHELL is the code it left unguarded.
- **Catch**: verify.sh runs `cargo test --workspace --locked -q` after the gate demos and fails closed on any failure, with the final line unchanged. Fail-closed gate (preference 3): the shell's correctness is not provable until the shell itself is verified (C18's open item).
- **Evidence**: with `pem_blocks` changed to accept non-blank lines outside a block (`(None, None, None) => {}`), the gate's command fails: `loader_fails_closed --- FAILED` at `crates/server/tests/shell.rs:66`, `verify.sh: cargo test failed`, exit 1. Restored afterwards.

## 2. Two 9a bugs were live on main while their fixes sat on an unmerged branch

- **Defect**: the CRYPTO window anchored at the read offset (RFC 9000 §7.5 floor, fixed by fcf9ff0, 3b23dbf) and the empty STREAM frame extending the receive buffer (fixed by 8f6b48e) were fixed and reviewed on phase-9a but still on main.
- **Escape**: the phase workflow merges once per phase, so a reviewed bug fix waits for the phase's last task; 9a's last tasks (3b, 5, 3c') are multi-session.
- **Class**: C3 CARRYOVER IN PROSE (the fix's location was tracked only in the ledger).
- **Catch**: process ruling (ledger, 2026-11-07): a task that fixes a bug present on main triggers a merge of the branch once its review passes, not at phase end. Not mechanical yet; 9r2's carryovers gate owns the mechanical form (a ledger line naming a main bug fix with no merge commit containing it fails).
- **Evidence**: this audit found both on main 14a6cf1. The merge commit that lands them is named in the 9a ledger and in `git log --merges main`.
- **Trade recorded at merge (9a final review I2):** T3's re-anchoring replaced the proved `buf_len <= 16384` with `<= unread + 16384`; the unread in-order part is bounded at runtime by quictls's drain, proved by Task 3b. TRUSTED.md carries the row until 3b merges.

## 3. Four getrandom calls per `Rand`

- **Defect**: `crates/server/src/lib.rs`'s `rand` filled each of `Rand`'s four arrays with its own `rng` call, so every routed datagram made four `getrandom` syscalls. Fixed in f273352 (one call, split).
- **Escape**: the shell has no cost model (ct-check's cost bounds cover crates/crypto only) and no test counted calls; review read the code for correctness, not syscall count.
- **Class**: C15 ALGORITHMIC COST (cost not pinned), in C18 UNVERIFIED SHELL.
- **Catch**: the test `one_rng_call_per_datagram` (`crates/server/tests/shell.rs`) counts `rng` calls through a counting `Rng` and pins one per datagram; verify.sh now runs it (§1). A test (preference 4): the shell is unverified, so no proof obligation can state it yet.
- **Evidence**: with f273352^'s `lib.rs`, the test fails `left: 8, right: 2`.
