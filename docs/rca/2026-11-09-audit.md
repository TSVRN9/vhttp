# RCAs from the 2026-11-09 audit

One section per finding of `docs/audit-2026-11-09.md` fixed in Phase 9r3, in the README's entry format.

## F5: a green verify run did not name its tree or its Verus

- **Defect**: `scripts/verify.sh` read the working tree and never checked it was clean, so an uncommitted edit under `crates/` gave a green run that described another tree (the mutants gate reads `HEAD` objects). `tools/rl.py --gate` ignored the JSON's `verus.version`, `verus.commit` and `verus.toolchain` and `is-verifying-entire-crate`; a handmade JSON with a bogus version and a partial run passed. `VERUS_HOME` defaulted to a path hardcoded in three scripts and was env-overridable, so a different Verus could produce the green line.
- **Escape**: no check compared a run's inputs with what the final line claims. The rlimit gate checked rows and the cap, not who produced them; the demos only varied rows.
- **Class**: C4 GATE FAIL-OPEN (a gate that passes without checking what the run was over).
- **Catch**: `scripts/clean-tree.sh` runs first in verify.sh and stops on a dirty tree; `VERIFY_DIRTY=1` runs on, prints `verify.sh: tree dirty, not a main-tip run` and the final line starts `verify.sh (DIRTY TREE, vouches for no commit):`. `cargo metadata --locked` fails a `Cargo.lock` cargo would rewrite. verify.sh records HEAD at the start and re-runs `clean-tree.sh ROOT HEAD` before the final line, so a commit or an edit made mid-run fails the run (under `VERIFY_DIRTY=1` it takes the DIRTY prefix). `tools/verus-pin.txt` (version, commit, toolchain) is the single source: the three scripts derive the default `VERUS_HOME` from it, and `rl.py --gate NAME --pin FILE` checks every results object against it and requires `is-verifying-entire-crate` true; a missing or malformed pin, or no `--pin`, fails.
- **Evidence**: gate-demos: `clean-tree: untracked file`, `clean-tree: modified tracked file`, `clean-tree: not a repo`; `rlimit-gate: wrong Verus version`, `wrong Verus commit`, `wrong toolchain`, `toolchain prefix without the dash`, `partial run`, `no verus object`, `missing pin file`, `pin file without commit and toolchain`, `no --pin`; the unchanged fixtures pass (`tools/gate-demos/rlimit/quic.json` now carries the matching `verus` object). verify.sh's own wiring: `verify.sh: dirty tree stops the run`, `verify.sh: a Cargo.lock cargo would rewrite`, `verify.sh: cargo not on PATH` (the last two print `cargo metadata --locked failed`, each before any Verus step); the end-of-run re-check: `clean-tree: HEAD moved during the run`, `clean-tree: tree dirtied during the run`.

## F17: a new dependency outside crypto passed every gate

- **Defect**: `scripts/deps-gate.sh` checked only that crypto's normal dependencies are exactly vstd. Any other crate (wire, h3, quic, quictls, tls, server, ctcore, ctmir) could gain a third-party dependency, or crypto's neighbours could change which crates they pull in, and no gate looked. Its `cargo tree` call also lacked `--locked` (verify.sh's `cargo metadata --locked` came with F5).
- **Escape**: the gate was written for the one crate the no-dependency rule was stated about (crypto); "no new dependencies" for the rest of the workspace was a plan sentence with no list to compare against.
- **Class**: C4 GATE FAIL-OPEN (a gate that checks one instance of a rule that names a set).
- **Catch**: `tools/deps-allow.txt` has one line per workspace crate, `CRATE: DEP ..` (normal depth-1 deps, names only, sorted; workspace crates included). `scripts/deps-gate.sh ROOT [TREEDIR]` runs `cargo tree -p C -e normal --depth 1 --prefix none --locked` for every crate under `crates/` and requires the sorted first tokens to equal the line exactly. A crate without a line, a line without a crate, a duplicated line, an empty tree, an empty allow-list or a cargo failure fails. Adding a dependency now means editing the allow-list in the same commit, which review sees.
- **Evidence**: gate-demos: `deps-gate`, `deps-gate: crypto with a second dep`, `an extra dep in another crate`, `vstd listed twice`, `a dep removed`, `crate without a line`, `line for a removed crate`, `empty tree`, `missing tree`, `empty allow-list`, `cargo tree fails`.
