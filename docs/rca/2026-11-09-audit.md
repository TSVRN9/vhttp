# RCAs from the 2026-11-09 audit

One section per finding of `docs/audit-2026-11-09.md` fixed in Phase 9r3, in the README's entry format.

## F5: a green verify run did not name its tree or its Verus

- **Defect**: `scripts/verify.sh` read the working tree and never checked it was clean, so an uncommitted edit under `crates/` gave a green run that described another tree (the mutants gate reads `HEAD` objects). `tools/rl.py --gate` ignored the JSON's `verus.version`, `verus.commit` and `verus.toolchain` and `is-verifying-entire-crate`; a handmade JSON with a bogus version and a partial run passed. `VERUS_HOME` defaulted to a path hardcoded in three scripts and was env-overridable, so a different Verus could produce the green line.
- **Escape**: no check compared a run's inputs with what the final line claims. The rlimit gate checked rows and the cap, not who produced them; the demos only varied rows.
- **Class**: C4 GATE FAIL-OPEN (a gate that passes without checking what the run was over).
- **Catch**: `scripts/clean-tree.sh` runs first in verify.sh and stops on a dirty tree; `VERIFY_DIRTY=1` runs on, prints `verify.sh: tree dirty, not a main-tip run` and the final line starts `verify.sh (DIRTY TREE, vouches for no commit):`. `cargo metadata --locked` fails a `Cargo.lock` cargo would rewrite. verify.sh records HEAD at the start and re-runs `clean-tree.sh ROOT HEAD` before the final line, so a commit or an edit made mid-run fails the run (under `VERIFY_DIRTY=1` it takes the DIRTY prefix). `tools/verus-pin.txt` (version, commit, toolchain) is the single source: the three scripts derive the default `VERUS_HOME` from it, and `rl.py --gate NAME --pin FILE` checks every results object against it and requires `is-verifying-entire-crate` true; a missing or malformed pin, or no `--pin`, fails.
- **Evidence**: gate-demos: `clean-tree: untracked file`, `clean-tree: modified tracked file`, `clean-tree: not a repo`; `rlimit-gate: wrong Verus version`, `wrong Verus commit`, `wrong toolchain`, `toolchain prefix without the dash`, `partial run`, `no verus object`, `missing pin file`, `pin file without commit and toolchain`, `no --pin`; the unchanged fixtures pass (`tools/gate-demos/rlimit/quic.json` now carries the matching `verus` object). verify.sh's own wiring: `verify.sh: dirty tree stops the run`, `verify.sh: a Cargo.lock cargo would rewrite`, `verify.sh: cargo not on PATH` (the last two print `cargo metadata --locked failed`, each before any Verus step); the end-of-run re-check: `clean-tree: HEAD moved during the run`, `clean-tree: tree dirtied during the run`.

## F17: a new dependency outside crypto passed every gate

- **Defect**: `scripts/deps-gate.sh` checked only that crypto's normal dependencies are exactly vstd. Any other crate (wire, h3, quic, quictls, tls, server, ctcore, ctmir) could gain a third-party dependency, or crypto's neighbours could change which crates they pull in, and no gate looked. Its `cargo tree` call also lacked `--locked` (verify.sh's `cargo metadata --locked` came with F5).
- **Escape**: the gate was written for the one crate the no-dependency rule was stated about (crypto); "no new dependencies" for the rest of the workspace was a plan sentence with no list to compare against.
- **Class**: C4 GATE FAIL-OPEN (a gate that checks one instance of a rule that names a set).
- **Catch**: `tools/deps-allow.txt` has one line per workspace crate, `CRATE: DEP ..` (normal depth-1 deps, names only, sorted; workspace crates included). `scripts/deps-gate.sh ROOT [TREEDIR]` runs `cargo tree -p C -e normal --depth 1 --prefix none --locked` for every crate under `crates/` and requires the sorted first tokens to equal the line exactly. A crate without a line, a line without a crate, a duplicated line, an empty tree, an empty allow-list or a cargo failure fails. Adding a dependency now means editing the allow-list in the same commit, which review sees.
- **Evidence**: gate-demos: `deps-gate`, `deps-gate: crypto with a second dep`, `an extra dep in another crate`, `vstd listed twice`, `a dep removed`, `crate without a line`, `line for a removed crate`, `empty tree`, `missing tree`, `empty allow-list`, `cargo tree fails`.

## F13: interop never re-checked; deleting a test stayed green

- **Defect**: `crates/server/tests/interop.rs` (curl and quiche clients against the server) is `#[ignore]` and skips silently when a client is absent, so `scripts/verify.sh` never ran it: a change that broke a real client stayed green. `scripts/test-gate.sh` required one passing test per crate, so deleting a vector test from a crate that kept another stayed green.
- **Escape**: the gate asked "did this crate pass anything" instead of "did it pass what it passed before". The interop tests were written as a manual Phase 4 exit check and never wired into the run that vouches for the tree.
- **Class**: C4 GATE FAIL-OPEN (a gate whose floor is zero-vs-nonzero) and C6 (a check that exists but is not run).
- **Catch**: `scripts/interop.sh ROOT` (run by verify.sh after the test gate) detects each client (curl with `HTTP3` in `curl --version`; quiche via `$QUICHE_CLIENT` or the main checkout's `ext-quiche` build), runs only the present clients' tests with `INTEROP_STRICT=1` and requires `test NAME ... ok`, and prints `interop: curl ok|skipped (no HTTP3), quiche ok|skipped (no client)`, so a skip is visible. `tools/test-floor.txt` (`CRATE COUNT`) is enforced by `test-gate.sh --workspace`: fewer passed tests than the floor, a crate with tests and no line, or a line naming no crate fails. The file only grows: `scripts/test-floor.sh` compares it with the merge-base's copy on a branch and `tools/ratchet_walk.py ... floors` walks the first-parent history on main (highest value per crate; a line once present cannot vanish). Deleting a test now means lowering the floor, which the ratchet refuses.
- **Evidence**: gate-demos: `interop: a present curl whose test fails`, `a present curl whose test printed neither ok nor FAILED`, `no HTTP3 and no quiche passes and says skipped`, `no interop.rs`; `test-gate: --workspace, a crate below its floor`, `a crate with tests and no floor line`, `a floor line naming no crate`, `an empty floor file`, `no floor file`; `test-floor: a lowered value against the merge-base`, `a removed line against the merge-base`, `main, growth then a drop`, `not a git checkout`. Residual: a floor is raised by hand when tests are added (a stale low floor still passes, but cannot be lowered later); interop skips on a machine with no client, and only the printed line shows it.

## F3: no roadmap in the repo; open work lived in a private note

- **Defect**: the only committed phase list (`docs/superpowers/specs/2026-10-27-verified-http3-design.md:83-124`) stopped at Phase 8. 9a-9c, 4d, the six trust-base sub-phases and the DoS work lived in specs, plan binding notes, gitignored ledgers and a private memory note outside the repo, and nothing tied a merged phase to the work it carried. TRUSTED.md's "Removed in phase" column named a phase that had merged (`8c follow-up`), phases with no plan (`Phase 6`, `Phase 7` where the Phase 9 spec moves the work after 9c), and `never` where the spec plans a proof (audit F18).
- **Escape**: carried work was prose (C3). The catalog proposed a tracked carryover file and its gate in 9r and no phase built it; TRUSTED's removal cell was free text that no gate read (C2).
- **Class**: C3 CARRYOVER IN PROSE; C2 STALE TEXT for the TRUSTED removal column.
- **Catch**: `docs/roadmap.md` lists every phase with its status and the owner's order, and `docs/carryovers.tsv` every carried item with an owner phase. `scripts/carryovers.sh` (in verify.sh; `tools/carryovers.py check`) fails when a row does not have the 6 columns, an id repeats, an owner is not a roadmap phase, a closed row's `test:`/`fn:`/`doc:`/`commit:` evidence does not resolve, a `merged` phase owns an `open` row, or a TRUSTED.md row's removal cell starts with neither a roadmap id nor `never (` and a reason, or names a merged phase. Rows are closed, never deleted: on a branch the tsv keeps every id of the merge-base's copy, on main `tools/ratchet_walk.py` (ids mode) every id of every first-parent copy. Fix round 1 (review I1, I2, M2, M9) anchors `merged`: a phase once merged stays merged (`ratchet_walk.py` merged mode, the same merge-base or first-parent rule), a merged row must name a commit that is an ancestor of HEAD, and every first-parent `Merge phase-<id>` / `Merge branch 'phase-<id>'` commit needs `<id>` (or the longest roadmap id it starts with) to be `merged`; `fn:`/`test:` evidence resolves only in tracked .rs files under crates/ or tools/ct-fixtures/, and `test:` needs `#[test]` above the fn; every id before a TRUSTED cell's first `(` must be a phase; an Evidence bullet's indented continuation lines are scanned too. Each TRUSTED row that names a phase has a carryover row (`tr-*`), so changing its cell to `never` leaves the open row behind.
- **Evidence**: gate-demos: `carryovers`, `carryovers: a closed row whose fn: does not resolve`, `fn: matches a whole name only`, `a closed row whose doc: is not tracked`, `a closed row whose commit: does not exist`, `an owner not in the roadmap`, `an open row owned by a merged phase`, `a TRUSTED row naming a merged phase`, `a duplicate id`, `a row with 5 columns`, `a TRUSTED row with an empty removal cell`, `a TRUSTED removal cell 'never'`, `'Phase 2'`, `'never ()'`, `main, a row deleted across two commits`, `a branch deleting a row of the merge-base`, `main, a row closed rather than deleted` (passes), `an empty tsv`, `a tsv with a header only`, `a missing roadmap file`, `a roadmap table with no rows`, `a missing TRUSTED.md`, `not a git checkout`, `no main branch to compare with`; fix round 1: `main, a merged phase un-merged across two commits`, `a branch un-merging a phase of the merge-base`, `a merged phase naming no commit`, `a merged phase naming a commit off HEAD's history`, `a Merge phase-2 commit while 2 is in progress`, `a merge of a branch that names no phase`, `fn: evidence found only in a gate-demos fixture`, `a non-test fn cited as test:`, `a TRUSTED cell whose second id is not a phase`, `an Evidence continuation line citing a worktree`. Residual: closing evidence is checked to exist, not to close the item; a phase merged by a commit whose subject does not name `phase-<id>` is tied to its status only by the merged ratchet once someone flips it; TRUSTED rows have no ids, so a `never (...)` cell is not ratcheted itself (the `tr-*` rows are); on the branch that introduced the tsv and the roadmap the merge-base has neither, so a row added and dropped before the first merge to main is not seen (74ddaed to the fix round's tip was diffed by hand: no id was dropped).

## F19 follow-up: committed docs cited evidence in deleted untracked dirs

- **Defect**: `docs/rca/2026-11-06-empty-crypto.md:8`, `docs/rca/2026-11-06-phase-9a-night.md:8,16,50` and the comments at `crates/ctmir/tests/eval.rs:147,172` cited logs under `.worktrees/vt-*-evidence`, which were deleted on the owner's F19 decision, so the evidence those lines named was gone. Rewritten to the mutant registry ids (re-run by `scripts/mutants.sh run`), test names and commits (7c2f1e0).
- **Escape**: run logs were kept where they were produced, in gitignored worktrees. The README's entry format asks for a demo, a mutant or the failing output without saying where that output may live, and no check read the citations.
- **Class**: C3 (untracked evidence).
- **Catch**: `tools/carryovers.py` fails on `.worktrees/`, `.superpowers/`, `/tmp/` or a `vt-*-evidence` dir in a tracked `docs/rca/*.md` Evidence line (both `**Evidence:**` and `**Evidence**:`), TRUSTED.md, docs/requirements.md or a tracked `crates/**/*.rs` line.
- **Evidence**: gate-demos: `carryovers: an RCA Evidence line citing a worktree evidence log`, `the other Evidence spelling, a bare evidence dir name`, `a crates .rs comment citing an evidence dir`. 9a2's `docs/rca/2026-11-07-audit.md:56` had the same defect and was rewritten on phase-9a2 (fceacf3; carryover `x-9a2-evidence`); had it not been, the gate would fail on it when it reaches main. Residual: specs, plans and the catalog still name the gitignored ledgers as their sources; those are provenance, not evidence lines, and are not scanned.

## F9: requirements.md marked unproved rows done

- **Defect**: `docs/requirements.md` ticked 255 of 466 rows with ✅ and a file path, and the tick meant "implemented", not "proved". `:257` (RFC 9000 §9.4) was ticked while TRUSTED.md's tr-37 row says its old-path MUST NOT is false today; `:387`, `:531`, `:533` were ticked with "pinned by tests, not proved" in their own notes; `:540`, `:423`, `:409`, `:204`, `:89` carried stale text (an `external_body` "until 5" after 5e merged, constant time as "a non-goal" after 8a-8d, handshake properties "Phase 4" after 4c). Choosing a `proved:` name for every ticked row (from the row's citation site and the fn or theorem whose ensures names the cited spec fn) unticked 114 more: rows whose MUST is "treat as a connection error of type X" prove the detection and the code at the detecting fn (`Streams::on_frame`, `parse_frame`, `parse_transport_params`, `PeerCids::on_new_cid`, `H3Conn::on_stream_data`), but no ensures pins X on the close or reset that reaches the QUIC wire (`Connection::on_frame` ensures only `c <= VARINT_MAX`; `H3Server::apply_one` passes codes through `wire_code`); rows whose subject is the unverified shell or operator config (CID routing updates, flow label, ECN, DF, ICMP, chain metadata); rows proved per state but stated by the RFC over history (§9.5, tr-38); rows whose property holds in code but in no ensures (RFC 9001 §4.1.2, §4.9.1); and rows that are vacuous rather than proved (the TLS record layer replaced by QUIC, zero-length connection IDs, exporters: now `n/a`; sending a Stateless Reset and 0-RTT keys: now `declined`).
- **Escape**: a tick was free text that no gate read, written by the phase that implemented the row from its own view of "done". The owner's rule that tested is open work, not done, was not encoded anywhere the matrix is checked; the matrix had no column naming the evidence, so a reader could not tell proved from tested from vacuous.
- **Class**: C1 DOC-OVERCLAIM (catalog proposal (2), evidence-tagged rows, built for requirements.md).
- **Catch**: a `Status` column on every row of the six RFC tables, checked by `scripts/requirements.sh` (`tools/requirements.py check`, in verify.sh): `proved:F` names must resolve as carryovers `fn:` evidence does (`tools/carryovers.py`'s `fn_found`, now shared) and name a fn in a `verus!` block under crates/ with an `ensures` (optionally `Type::fn`); `tested:T` must be `#[test]` fns and needs an `open:` owner; `false (ID)` needs an open TRUSTED.md carryover row and `open:` its owner; `open:P` must be an unmerged roadmap phase that owns an open `req-*` row citing requirements.md, so that phase cannot merge while the rows stay open; `N/A` and `Declined` phase cells need `n/a`/`declined`; a ticked row must have `proved:` alone; a table without the Status header, a row without it, no rows, a missing file or a git error fail. The legend's Phase 7 exit ("no unannotated MUSTs", not checked by `duvet report`) is carryover `req-duvet`.
- **Evidence**: gate-demos: `requirements` (the unchanged fixture passes), `requirements: a ticked row with tested: only`, `a proved: fn that does not exist`, `a proved: fn with no ensures`, `a tested: name that is not a #[test]`, `a row with no status`, `an open: id not in the roadmap`, `an open: id of a merged phase`, `an open: phase with no req- carryover row`, `tested: without an open: owner`, `a false key that is not a TRUSTED.md carryover`, `a false row without its owner`, `an N/A row whose Status is not n/a`, `a table without the Status column`, `no table rows`, `a missing requirements.md`, `not a git checkout (git did not run)`. Residual: the gate checks that a `proved:` fn exists and has an ensures, not that its ensures carries the row's requirement; that choice is the row's author's and the reviewer's. In 9r3 Task 6 the names were chosen from each row's citation site and the ensures naming the cited spec fn, not traced conjunct by conjunct; the rows whose conjuncts were then read (`poll_transmit`'s `responses_echoed`, `path_expanded`, `challenges_recorded`, `wf_amp`) kept their tick, the ones no ensures stated (§8.2.2's no-delay, the MTU re-validation, RFC 9001 §4) became `open:11`. A later refactor that weakens an ensures keeps the name valid. The RFC 8446 alert rows are judged at the TLS layer: converting an alert to a QUIC close is RFC 9001 §4.8's row.
