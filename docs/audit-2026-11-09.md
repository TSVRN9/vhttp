## Project rules that apply to every fix

These are the owner's standing rules. They are not optional.

- **No proof shortcuts.** Trust only rustc, LLVM, Verus and Z3. If a proof runs over its rlimit,
  restructure it. Never drop, defer or replace a proof with a test. No `assume`, `admit` or
  `external_body` (the escape gate counts 0 today and must stay 0).
- **Every error path proves the RFC requires it; every close proves the frame and code are sent.**
- **Every bug gets an RCA and a mechanical catch for its class.** RCAs go in `docs/rca/`, classes in
  `docs/rca/catalog.md`, catches in `scripts/verify.sh` with a fail-closed demo in
  `scripts/gate-demos.sh`. Read `docs/rca/README.md` first. Findings F2, F4, F5, F6, F7 are bugs or
  broken catches and need this treatment.
- **Merges to main are `--no-ff` only.** Before a merge, `scripts/verify.sh` must pass. Any change
  under `crates/`, the root Cargo files or `tools/mutants.tsv` needs a fresh `scripts/mutants.sh run`
  (about 10 min) so `tools/mutants-last-run.txt` matches the tree.
- Ratchet files only shrink: `tools/rlimit-ceilings.txt`, `tools/acceptance-baseline.txt`,
  `tools/rfc-quantity-open.txt`. quic and quictls functions have a hard 8,000,000 rlimit cap.
- Any edit in `crates/crypto` voids the binary digests; follow the update protocol in
  `docs/crypto-binary-audit.md`.
- Toolchain is pinned (Verus 0.2026.10.04.426d8b0, rustc 1.98.1, vest_lib 0.2.2). Do not upgrade.
- Work in a worktree under `.worktrees/` on a phase branch, never in `/tmp`.

## Findings

### Must fix

**F1. Work is not backed up.** (confirmed)
- 80 commits on `main` and all of `phase-9a2` exist only on one laptop. Task ledgers live in
  `.superpowers/` and `.worktrees/`, both ignored by git.
- Fix: `git push origin main phase-9a2`. **Needs the owner's go-ahead.** Consider whether the ledgers

**F2. A client can hold a connection slot forever without finishing the handshake.** (confirmed,
except one step)
- `Connection::on_packet` calls `self.idle.on_packet_processed(now)` for every packet kind, Initial
  included (`crates/quic/src/conn.rs:1208`; `crates/quic/src/lifecycle.rs:156`). Initial keys are
  public. `open_timeout` (`conn.rs:7619-7627`) has only idle, ACK, PTO and path terms: no handshake
  deadline. The Initial gate (`conn.rs:1132-1137`) needs only the handshake path, a matching SCID and
  a fresh packet number.
- Attack: one 1200-byte ClientHello Initial, then one Initial PING every 29 s from the same (spoofable)
  address. 102 such connections fill `MAX_CONNS`; `route` then drops every new Initial
  (`crates/quic/src/route.rs:1177-1178`). About 3.4 datagrams per second in total.
- The shell comment (`crates/server/src/lib.rs:200`) says a slot is held "up to 55.6 min". It is
  unbounded.
- Not traced: that `on_frames` accepts a PING-only Initial. Check this first; write the failing test.
- Fix: one handshake deadline in `open_timeout`, set at accept and never refreshed, with a proved
  close. Cite the RFC basis (RFC 9000 §10.1 lets an endpoint pick its own idle timeout; §8.1 and
  §21 discuss handshake DoS). This is a bug: it needs an RCA, a catalog class and a catch.

  six unnamed trust-base sub-phases "after 9c" at `:268-276`. "4d" (key update, AEAD limits) is
  defined only at `docs/requirements.md:19` and `docs/superpowers/plans/2026-11-05-phase-4c-quic-tls-glue.md:674-679`.
- No plan file exists for 9b, 9c, 4d, Phase 6 or Phase 7 beyond 7a.
- The open-work list lives in a private memory note outside the repo. The catalog names this as class
  C3 "carryover in prose" and its catch (`docs/carryovers.tsv` plus a gate) is still open

- Fix: one committed `docs/roadmap.md` with every phase, its status, order and carried-over items,

### Should fix

**F4. The mutant gate accepts a run that never happened.** (reviewer-confirmed)
- Every field of `tools/mutants-last-run.txt` can be computed from git: `rev-parse HEAD:crates`,
  `mutants.py tree . HEAD`, the tsv blob, and `<id> pass <patch blob>`. Regenerated from `HEAD`
  without running a mutant, it equals the committed file except the `#` line. `mutants.sh verify`
  accepts it (`tools/mutants.py:155-190`). The file names neither the Verus version nor the scripts.
- Fix options: run `mutants.sh run` inside `verify.sh` at main's tip, or state in `docs/rca/README.md`
  and `TRUSTED.md` that the file is an attestation. The owner's "no shortcuts" rule points to the first.

**F5. A green verify run is not tied to the commit or to the pinned Verus.** (reviewer-confirmed)
- `scripts/verify.sh` reads the working tree and never checks it is clean; the mutants gate reads
  `HEAD` objects. An uncommitted edit under `crates/` gives a green run that describes another tree.
- `tools/rl.py:86-103` ignores the JSON's `verus.version`/`commit` and `is-verifying-entire-crate`.
  A handmade JSON with a bogus version, `is-verifying-entire-crate: false` and one row passed
  `--gate quic --max 8000000`. `VERUS_HOME` is env-overridable.
- Fix: fail `verify.sh` on non-empty `git status --porcelain` (decide how local runs on a dirty tree
  should work, e.g. a flag that prints "tree dirty, not a main-tip run"); make `rl.py` check the
  version against the pin and require whole-crate verification. Add demos.

**F6. The acceptance gate skips error paths that do not return `Result`.** (reviewer-confirmed
against real source)
- Not counted today:
  - `quic::streams::Streams::check -> Option<u64>` (`crates/quic/src/streams.rs:1067`)
  - `h3::uni::control_header_error -> Option<u64>` (`crates/h3/src/uni.rs:667`)
  - `quic::h3_server::wire_code -> u64` (`crates/quic/src/h3_server.rs:219`)
  - `quictls::server::QuicServer::{superseded, key_changes, on_params, on_complete} -> bool`
    (`crates/quictls/src/server.rs:611,792,832,919`)
- The clause check is a name match (`tools/acceptance.py:336-338`). These passed in isolation:
  `ensures r is Ok ==> allowed_x_err(x)` (wrong polarity), `ensures allowed_y_err(0) || true`,
  predicate bodies `c == c` and `true || c == 1`. The 3 real carriers today are well-formed.
- Fix: widen the gate to these return shapes (or add them to the baseline by hand, which grows a
  shrink-only file and so needs the ratchet rule for it), and require the
  `r matches Err(c) ==> allowed_…(c)` shape. Demos for each bad spelling.

**F8. The top-level API does not state end to end what the lower layers prove.** (read-only)
